# line-notation

**Fires when** — a relation deserves an edge but not a block: one link inside a
flowing sentence · a row in a table · a fork where full branch-geometry would
cost more attention than it activates. The medium is a single line.

**Form** — the same graph, flattened into a row. The edges are what survives
the projection: 2D block → one line → prose, and at each step the glyphs are
what still carries structure ⊸ lose them and you have decoration.

Three shapes, from lightest to heaviest:

1. *Chained peers* — the middle dot strings equal items where commas would
   blur into prose: `verify from source · measure, don't argue · short commits`
2. *Edge inside a sentence* — clause + glyph + node, inline:
   `…and whatever I have not named ⇝ tunnel vision`
   `a choice without candidates ∴ widen first`
   The glyph binds the clauses around it; the node may stay bare or bracketed.
3. *Flattened fork* — a choice with honest consequences, trunk geometry dropped,
   two columns kept:

   ```
   [heavy work ahead]
              ◇
   pulse first            straight in
   you see the wall       the hit arrives
   before the hit         blind
   ```

   Both columns are written as *consequences*, not labels — the reader chooses
   between futures, not between names.

**Example** — live, translated from a working project brief (which contains no
legend of its own: it relies on a reader already trained by the companion
document — see Cost):

> Before generating a reply — pick what this moment is, with identification ∴
> proposing an action · reporting work done · explaining a mechanism ·
> …and the unnamed one ⇝ (curse of knowledge) · (burying the lede)

One row; six typed relations; the prose version would be a paragraph — and would be
skimmed.

**Why** — write little, activate much: the row costs almost nothing inside
running text, but the relation stays typed and the node names stay vectors into
what the reader-model already carries. The move has prior art outside AI:
chemists flatten molecular graphs into rows the same way — SMILES: "a line
notation (a typographical method using printable characters)", "a linguistic
construct, rather than a computer data structure", 50–70% more compact than
the equivalent connection table (Weininger/Daylight,
[REFERENCES #4](../REFERENCES.md)). The family name is **line notation**;
this is its context-document member.

**Cost / when not**

- **Presumes a trained reader.** A row carries no legend. If the legend was
  never read — in this document family, or in the companion always-loaded
  file — the glyphs degrade to noise. Line notation is the *second* document's
  form; the first document teaches the edges. (→ pattern: legend)
- **Flattening loses the trunk.** Nested forks and deep branch-geometry do not
  survive one line — when the structure fights the row, return to the
  graph-block.
- **Do not redefine common punctuation** as edges (the known failure of
  invented notations), and **scope existing symbols** whose dominant meaning
  differs from yours.
- **One dialect per document family.** The same glyph carrying different
  meanings in sibling documents is a measured internal failure mode — the
  vocabulary must be versioned once, not re-invented per file.
